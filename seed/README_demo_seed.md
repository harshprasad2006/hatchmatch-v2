# problems_demo_seed.json (DEMO ONLY)

**This is synthetic test data. It is NOT from a real survey.**
Never present these records as real survey results, and never mix them with real survey records.
Use it only for testing prompts (Member 3), the Real problems list page (Member 2) and the full app test.

## What is inside
10 records, JSON array, UTF-8. Every `id` starts with `demo-` so they are easy to find and delete.
Languages: Hindi (3), Marathi (3), English (1), Mixed (3).

## Fields
| Field | Meaning |
|---|---|
| `id` | `demo-s01` to `demo-s10` |
| `rawText` | The problem text as written (Q1) |
| `language` | Hindi, Marathi, English or Mixed |
| `card.title` | Short title (written by us, not by AI) |
| `card.who` | Who faces it. "Me" became "Individual users" |
| `card.pain` | The pain in one line |
| `card.frequency` | Daily, Weekly, Monthly, A few times a year |
| `card.workaround` | What the person does today |
| `card.category` | One of the survey categories |
| `existingSolutions` | Empty list on purpose. No fake links |
| `shared` | `true`, so they show in the Real problems list |
| `createdAt` | Provisional ISO date string |

Not included (not in the core schema): votes, interestedBuilders, and the survey answers for "used an app?" and "impact 1 to 5".

## Assumptions (not verified against the repo)
1. The backend accepts these field names exactly as listed in the plan.
2. `createdAt` must probably be a Firestore Timestamp. The import script should convert the string.
3. `existingSolutions` structure is unknown. An empty list is used.
4. Import format (array or separate documents) and whether `id` comes from the file are unknown.
